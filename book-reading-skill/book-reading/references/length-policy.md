# 文章字数硬约束

## 计数口径

- 使用**正文净字数**：不计 YAML 元数据、首个 H1（总标题）、封面图片、URL 和 Markdown 标记符号（`#`、`*`、`_`、`>`、`-` 等）。
- 其余文字（节标题文字、引用块、正文）中的**汉字每个计 1**；**连续英文或数字作为一个 token 计 1**。
- 必须使用 `scripts/check_length.py` 计数，**不凭编辑器或视觉估算**。

## 状态规则

- `1000-1200`：`ready`，允许交付。
- `900-999` 或 `1201-1320`：`needs-length-review`，属上下 10% 容差带，必须继续补写或压缩，不能直接交付。
- `<900` 或 `>1320`：`rejected`，禁止交付。
- 默认交付必须位于 `1000-1200`；容差带只用于发现偏差，不是常规目标。

## 三个核心部分的篇幅建议

- 开头（钩子 + 点题）：110-130 字。
- 第 1 节：260-310 字。
- 第 2 节：260-310 字。
- 第 3 节：260-310 字。
- 结尾（「写在最后」+ 核心金句 + 鼓励）：110-130 字。

> 各部分取值任意组合都落在 1000-1200 目标区间内（上限组合 130+3×310+130=1190）。

## 强制检查节点

1. 初稿完成后运行一次。
2. 终稿交付前再运行一次，避免增删造成篇幅漂移。

```
python "<SKILL_DIR>/scripts/check_length.py" "<article-path>" --json
```

只在脚本返回 `ready` 且退出码为 `0` 时，才允许交付。
