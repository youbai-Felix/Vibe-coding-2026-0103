# 洞见风格读书解读写作包（标准版）

一个不绑定任何人设的通用写作引擎。产出「洞见」风格的读书解读文章，任意账号可直接使用。本包默认**不植入个人 IP、不暴露作者姓名**，以第二人称「你」和普世视角展开。

`SKILL.md` 所在目录记为 `SKILL_DIR`。写作前必须读取 `references/` 下全部文件：**`writing-credo.md`（写作心法，动笔前+终稿前必读）**、`style-profile.md`（洞见机制）、`structure-policy.md`（骨架）、`length-policy.md`（字数）、`banned-phrases.md`（禁用词与套话）、`persona-method.md`（招牌动作 / 爆款 / 推荐隐晦 / 禁区；标准版参考其中的通用部分，如「推荐隐晦」）、`persona.md`（人设插槽）、`ip-integration.md`（人设植入协议）。

## 0. 写作心法（动笔前 + 终稿前必读）

`references/writing-credo.md` 是整个引擎的灵魂，整合了洞见风格、卡兹克方法、实战反馈。六条心法：**①赋神不赋形**（形是脚手架非模板，换主题换书也能原样用=套路）·**②实事求是准确第一**（不编造，情绪用体感不用知识性描述）·**③一人一书一痛点**（只围绕一本书，靠打动不靠推销）·**④开头和主题咬合不套路**·**⑤像真人不是AI**（通读自检温度/独特/心流）·**⑥骨架可依不被困住**。冲突时以心法为准。

## 1. 输入

接受以下任一：
1. **一篇文章正文**（粘贴文本或文件路径）→ 提取原标题与主题。
2. **一个选题 / 一句话痛点**（如「为什么人越长大越孤独」）→ 按选书规则选书。
3. **一本书名** → 直接围绕该书。

若用户只给链接，先用可用方式读取（请用户粘贴正文优先）；读不到正文时如实说明，**不得只凭标题写作**。

## 2. 选书（固定顺序，不得跳级）

> **不论输入是什么（一篇文章 / 一个选题 / 一句话），最终产出都必须是围绕一本书的解读。** 输入无书名时，严格按下面顺序选最合适的书——不得写成无书的泛论。

1. 输入有明确书名 → 用该书。
2. 无书名但有明确名人 → 用该名人代表著作。
3. 两者皆无 → 选最适合主题的全球名著或可靠专业书。

> **选书偏好（2026-08-09 用户定）**：在贴合主题的前提下，**优先选热门、大众熟知、畅销的书**（共鸣广、带货转化高）。少用冷门专业书；同一痛点有多本可选时，选知名度最高、读者最容易搜到买到的那本。

## 3. 原创写作

> **🔑 素材池调用（2026-08-13 游白定，必做，先于一切写作步骤）**
> 动笔前必须读取个人真实素材池：`AI书单公众号/素材池.md`（相对 vault 根 `自我进化系统/`）。
> 1. 从中挑一条 **🟩未用 + 主题匹配当前书 + 适合本篇人设** 的真实素材。
> 2. 这条素材要**作为至少一节的主体论据**写进正文（不是书中情节，是「你」的真实经历/观察）——这是规避「低价值 AIGC / 搬运书」判定的关键，平台要的是只有你才写得出的增量。
> 3. 用完后**回写素材池**：把该条状态 🟩 → 🟥，并标注 `号·书名·日期`。
> 4. 若池子无匹配（空池 / 无主题贴合）：照常出初稿，但**交付时必须明确告知游白**「本篇未注入真实素材，建议手补一段你的真实经历后再发」。
> 5. 一条独家素材只用一个号、一次；通用素材多号可用但需改角度、错开 3 天以上。

> **动笔前五问（落点先行）**：写第一句之前，先把这五个问题想清楚——它们是全文的内部约束，正文每一节都要服务于此。五问不必写进正文，但**写完若答不出「观点」或「落点」，推倒重写**。
> 1. **写给谁？** 覆盖哪类人群（年龄 / 处境 / 焦虑）——决定用词、例子、温度。
> 2. **解决读者什么问题？** 他带着什么困惑点开这篇文章——全文必须正面回应。
> 3. **我的观点是什么？** 用一句话讲清核心判断（≤25 字）——这是全文的脊梁。
> 4. **如何调动情绪？** 读完该有什么感觉（共鸣 / 不甘 / 被理解 / 松一口气）——决定钩子与节奏。
> 5. **给出什么解决方案？** 至少让读者带走一个认知或一个最小行动——落在结尾，别悬空。

> **⚠️ 最高原则：实事求是、准确第一（覆盖一切风格要求）**
> - **不编造反应**：写作者的动作与情绪必须真实。没真抄别写「我抄下来了」，没愣别写「愣了好久」，没做某事别写「合上书我做了件事」。「念原文 + 被打动的反应」这类招牌动作只在真有其事时用、且要说具体，不得每篇套路化套用。
> - **禁止不知所云的模糊表达**：每个判断都要具体、清晰、可被理解；禁用空泛金句（如「是个狠的」「他知道自己几斤几两，所以收得住」「没把自己弄丢」）——宁可把意思说白，不要漂亮但听不懂的调调。
> - **情绪克制，禁刻意用力**：不堆夸张的情绪词和反应（「反胃」「笑出声」「愣了好久」「彻底垮了」「气得」「丢人」）去逼读者感动。情绪点到为止，靠事实和细节自己说话。收着写，克制比用力更可信。
> - **禁用破折号**：不用破折号（—— / —）做停顿、补充或转折；该断句就用逗号或句号另起一句，把意思说清楚。破折号用多了显刻意、文艺腔。

1. 全文围绕**选定的一本书**，回应原标题/主题所面对的人生痛点。
2. 只迁移 `references/style-profile.md` 中蒸馏的**抽象机制**（骨架、金句、引用、情绪、短段落）。
3. **不得复用**来源文章的具体故事、人物、比喻、金句、论证顺序、段落或结尾。
4. **不得编造**书中没有的情节、名人未说过的话、虚假研究或数据。书里的事实拿不准就泛化处理或删去，不补写。
5. **规避 AI 味套话**：执行 `references/banned-phrases.md`——绝对禁用项（教科书套话、宏大叙事开头、书面填充、空洞升华）不得出现；「正如一句话所说」每篇 ≤ 3 次；**翻案腔族（不是 A 而是 B 等 11 种变形，含各节小标题）全文 ≤ 1 处**（`check_originality.py` 硬卡，首个 H1 照搬豁免）。
6. **推荐隐晦（带货号约束）**：全文只围绕选定的这一本书，**绝不推荐、提及别的书**；不写「快去看 / 必读 / 强烈推荐 / 这本你得看看」等明着推销的话（底部链接负责转化，文章只负责打动）。**目标效果：让读者意犹未尽、想亲自去书里游历一番**（只取一个切口、留"书里还有"的钩子，别把书讲尽）。详见 `references/persona-method.md`「推荐要隐晦」。

## 4. 骨架与格式（见 references/structure-policy.md）

**固定 3 节**。每节结构一致：
**加粗金句小标题 → 一段核心论据 → 延伸到现实 → 升华落到「你」**。

> **核心论据来源（2026-08-13 调整，降复述提原创）**：每节支撑可选 ①**个人真实素材**（优先，来自素材池，做主体）②书中情节（作引子，只点不展开，**单节 ≤ 100 字**）③现实观察/现象。**全文 3 节里至少 1 节用①做主体；书中情节全文合计 ≤ 300 字**——为规避「大篇幅整合他人作品 / 搬运」判定。详见 `references/structure-policy.md`。

- 开头：钩子（反问 / 名人名言 / 热点事件）+ 2-3 个极短点题段。
- 结尾：`# 写在最后` 标记 + 一段完整收束的话（末尾自然落到一句全书核心金句 + 温暖鼓励）。
- 推荐语（默认加）：全文最末尾另起一行 `👇👇读《书名》：金句`——一句戳人、带悬念的核心金句作导流收尾。

**三种必备 Markdown 样式（缺一不可，`check_style.py` 硬校验）：**
- **标题**：全文统一一级标题 `#`——文章总标题 + `# 01/02/03` 节标题 + `# 写在最后`（不用 ## / ###）。**文章总标题取法（2026-08-09 用户定）**：①若原文章/素材自带标题（微信 `og:title`、知乎问题标题等），**一律照搬原标题原文，不改、不截、不另起**；②若素材无标题（纯选题 / 书名 / 一段话），**列出 5 个候选标题供用户选，定稿后再写入**——候选要求：激发好奇（留悬念 / 反常 / 问句）、戳中目标读者最在意又最焦虑的那件事（呼应五问 1、2）、尽量 ≤ 18 字、能不用形容词就不用。
- **加粗**：每节开头的金句小标题用 `**加粗**`（全文 ≥ 3 处）。
- **引用**：书中原文、名人名言用 `>` 引用块呈现（全文 ≥ 1 处）。

## 5. 洞见机制（见 references/style-profile.md）

严格执行：段落极短（多数 1-2 句）、短句为主、高频转折（但/可/然而/殊不知）、第二人称「你」精准投放（不凑次数）、金句高密度、名人名言 + 书中原文引用块、治愈温暖的情绪温度。

## 6. 字数与风格校验

### 6.1 字数（见 references/length-policy.md）

正文净字数目标 **1000-1200**。初稿与终稿都必须运行：

```
python "<SKILL_DIR>/scripts/check_length.py" "<article-path>" --json
```

- `1000-1200` → `ready`，可交付。
- `900-999` 或 `1201-1320` → `needs-length-review`，必须继续改。
- `<900` 或 `>1320` → `rejected`，禁止交付。
- 不得凭视觉估字数，以脚本为准。

### 6.2 风格与禁用词（见 references/banned-phrases.md）

终稿必须运行：

```
python "<SKILL_DIR>/scripts/check_style.py" "<article-path>" --json
```

- **硬性项**（禁用词命中 / 缺「写在最后」/ 节数非 3）任一不通过 → 必须改到通过。
- **软性项**（「你」偏少 / 段落偏长 / 限频句式超标）为警告，尽量改。
- **两个脚本都通过（退出码 0）才允许交付。** 另见 §6.4 原创度检测——**check_length ready + check_style pass + check_originality 无 risks，三脚本全过才交付。**

### 6.3 活人感终检（写完通读，脚本之外）

脚本只查「形」（字数 / 禁用词 / 三样式），查不了「神」。交付前再通读一遍全文，问自己一个问题：**这篇像真人在跟你聊一件打动他的事，还是 AI 在输出信息？** 三个维度任一不过，返工对应段落（无机械修复法，靠改写）：

1. **温度感**：情绪是体感记忆（「我读到这句，停了很久」），还是知识性描述（「我深受震撼」「发人深省」）？后者是 AI 味的典型破绽，换成具体动作或体感。
2. **独特性**：这段话换成别的博主 / 别的人设，是不是也能写出来？如果是，说明没织进本人设的声音，删通用套话、换成只有这个人会说的话。
3. **心流**：从头读到尾，有没有哪个地方注意力断掉、要回头理逻辑？断点就是节奏 / 转场要修的地方。

> 这一层的标准最高也最主观：宁可删掉一段「正确但 AI 味」的话，也不要留着凑数。

### 6.4 原创度 / AI 味自检（2026-08-14 加，规避「低创作度 / 滥用原创」）

终稿必须运行（与 check_length / check_style 并列）：

```
python "<SKILL_DIR>/scripts/check_originality.py" "<article-path>" --json
```

专查 check_style 不覆盖的 **AI 味形状特征**（微信判「低价值 AIGC」的信号）：
- **硬性 risk（清零才交付，退出码 1）**：翻案腔变形族（不是A而是B 等 11 种）正文 ≤ 1（首个 H1 标题照搬豁免）。
- **软性 warning（建议改）**：句长变异系数 < 0.40（句长太齐=模型腔）/ 「」金句密度 > 3/千字（批量造金句）/ 连词密度 > 7/千字 / 连续 ≥4 段同一开场词。

**有 risks 必须修到 0 再交付**：翻案腔改写成正面判断、长短句交错、删多余金句、换开场词，改完重跑直到无 risks。

> ⚠ **本脚本只覆盖「低价值 AIGC 形状」类风险**。「搬运 / 整合他人作品」类风险（复述版权书、缺真实素材）脚本查不了，靠 §4 书引子化（书情节 ≤ 300 字）+ 公版书 + §3 素材池真实素材——三者结合才完整。实测：5 篇按新规则写的全 pass；被判违规的《遥远的救世主》也 pass（说明它栽在「复述版权书」而非「AI 味形状」，脚本查不到那层）。

### 8.2 封面（只抓文章原图，不自己设计）

- **抓不到原图就不放**：不生成任何替代封面，标题后直接接正文，并告知用户。
